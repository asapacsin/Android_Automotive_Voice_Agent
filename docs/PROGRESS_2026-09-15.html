阶段进展报告

小诺 · Android 车载语音助手

基于百度端到端语音语言大模型的车载语音代理。本阶段目标：让手机在输入凭证后独立运行完整语音链路，不依赖 PC、局域网或调试工具。

日期 2026-09-15 版本 0.6.0-baidu-flex 测试 129 项 / 0 失败 真机 小米 24069RA21C · Android 36

一、系统架构

采用端到端语音模型，模型直接接收原始音频并直接输出结构化函数调用，不经过「语音识别 → 文本大模型 → 语音合成」的传统三段式流水线。界面上显示的文字是百度随音频下发的字幕旁路，仅供显示，不参与决策。

手机麦克风 → 16 kHz 单声道 PCM16 → 百度 Flex 实时模型 → function_call → 车机动作执行 → 语音回复

模型为 qianfan-realtime-flex-v1，经 WebSocket 直连 aip.baidubce.com。会话通过 session.update 下发人设、音色与工具定义；语音上行使用 input_audio_buffer.append；服务端语音活动检测负责断句与打断。

二、本阶段完成的工作

  • 01

    手机独立运行

    正常语音流程不再需要 PC 后端、局域网或 ADB。构建产物中不含任何后端地址。
  • 02

    凭证安全

    App ID、API Key、Secret Key 与高德 Key 全部经 Android Keystore 加密存储，支持保留／替换／显式清除。源码与安装包扫描均未发现明文密钥。
  • 03

    函数调用能力

    实现 navigate_to 与 open_app。模型输出的参数先经字段白名单、长度与枚举校验，未通过则拒绝执行，不直接信任模型输出。
  • 04

    导航落地

    语音说出目的地后，应用先将名称解析为坐标，再以坐标深链唤起高德地图，零点击直接进入实时导航。支持按当前位置就近检索。
  • 05

    后台存活

    引入麦克风类型前台服务，解决地图占据前台后语音会话被系统切断的问题。
  • 06

    人格与音色

    人设经会话 instructions 下发，可在开发者设置中修改；音色与语速可配置，并在服务端拒绝时自动回退默认值，避免会话建立失败。
  • 07

    音频质量

    修正回放采样率（Flex 默认 24 kHz，可切换 16 kHz），增大播放缓冲，启用回声消除与噪声抑制。
  • 08

    字幕显示

    改为仅显示完整语句。此前逐字增量显示，视觉上容易被误认为语音识别流。

四、关键技术问题与解决

问题 · 导航停在选择列表

高德地图仅在深链中带有经纬度时才会自动开始导航；仅传目的地名称的深链一律停在「输入终点」候选列表，需要人工点选，不满足驾驶场景。

解决：应用内先调用高德 Web 服务接口把名称解析为坐标，再以坐标深链唤起导航。已在真机验证可零点击进入导航。

问题 · 后台连接被系统切断

应用退到后台约 5 秒后，系统销毁其 TCP 连接（日志可见 Destroyed live tcp sockets），语音会话随即以 BAIDU_FLEX_DNS_FAILED 中断。

解决：改用麦克风类型前台服务并保持常驻通知。实测地图前台运行期间会话与录音均保持正常。

认知澄清 · 并非语音识别方案

界面上逐字出现的文字曾使人误认为系统退化为「识别 + 文本模型」架构。

澄清：模型直接消费音频并直接产出函数调用，文字仅为服务端下发的字幕旁路。为避免歧义，界面已改为只显示完整语句。

问题 · 方言回复与自激

实测发现两项缺陷：其一，模型曾以粤语回复，尽管人设已要求只用简体中文；其二，应用自身播放的音乐经扬声器被麦克风拾取，服务端语音活动检测持续判定为「用户正在说话」，模型因而应答自己播放的声音。

自激问题已修复并实测通过：提高服务端语音活动检测阈值、降低内置音乐音量后，播放音乐 18 秒期间误触发次数为 0。系统自带的回声消除仅作用于通话下行、不覆盖媒体播放，因此从阈值与音量两侧抑制。方言问题已按同一版本修改人设（强制普通话、禁止粤语与方言），待人工语音复核。
