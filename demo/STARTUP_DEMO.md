## 一页纸（交给导师 / 评委的文字版）

**问题。** 车上的语音助手只听得懂固定口令：「打开车窗」可以，「有蚊子」不行。司机得先想好怎么说，等它一句句确认，分心又慢。

**我们做的。** 小诺是一个装在车机（Android）上的语音助手。司机像跟人说话一样说，小诺听懂意思，直接把事办完，用一个固定的、有性格的声音回答。

**和别人不同的三点。**
1. **听懂模糊的话。**
   - 「有蚊子」→ 车窗开一半，等蚊子飞出去；「出去了」→ 关窗。
   - 「座位有点高」→ 降一档；「再低一点」→ 从上下文知道说的是座椅。
   - 意思不明确时，只问一句：「座椅还是温度？」
2. **说到就做到，做不到就直说。**
   - 每个动作都由程序执行并确认结果，小诺只说真正完成了的事。
   - 模型说「已经帮你打开了」，但实际没执行，这句话会被拦下、改正。
   - 做不到的事，例如天窗，她会直说「暂时不支持」。
3. **一个声音，一个性格。**
   - 全程只有一个声音：Azure 晓伊。
   - 可以随时换说话风格：傲娇、嗲、温柔、元气。变的是语气，不只是用词。
   - 导航播报也由同一个声音说。
   - 司机可以随时打断她。

**技术。**
- **语音：** Gemini Live 端到端语音对话，带函数调用。
- **声音：** Azure 神经语音晓伊。
- **地图：** 高德导航 SDK 内嵌在我们自己的界面里。
- **把关：** 车控、导航、音乐都由确定性代码执行和把关，不靠提示词。

**现在在哪。**
- 能演示的：自然语言车控、导航、音乐、说话风格、打断，都在模拟器和测试手机上跑通。
- 底下有 3500 多个自动化测试。
- 车控目前接的是模拟车身，还没接真车 CAN。说的时候请照实说。

**下一步。** 接真车车身接口，并做量产延迟优化：把回答首句的延迟稳定压到 2 秒以内。

## 成片分镜（约 3 分 30 秒，五段，不要再加）

演示全程用短路线：**横琴创业谷 → 励骏庞都**。

| 段 | 时长 | 口令（用户声音） | 画面上应该看到 / 听到 | 右侧字幕要点 | 日志里必须有 |
| --- | --- | --- | --- | --- | --- |
| 0 片头 | 10 s | — | 地图首页 | 小诺：听得懂人话的车载助手 | — |
| 1 认识她 | 25 s | 「你好小诺」→「你能做什么？」 | 晓伊的声音回答能力；气泡出现，说完 10 秒后自动淡出 | 一个声音；对话结束后界面自己收拾干净 | `assistant_voice enabled=true`、`state=SPEAKING`、`transcript_bubble_faded` |
| 2 模糊车控（主场景） | 60 s | 「有蚊子」→「蚊子出去了」→「座位有点高」→「再低一点」→「温度调低一度」→「再低一点」 | 车窗开一半再关上；座椅降两档；温度 −1；最后一句她只问「座椅还是温度？」，不乱动 | 不用记口令；听上下文；拿不准就问 | `tool=run_scenario`、`tool=control_seat` ×2、`tool=control_climate`；最后一句没有 `tool=` |
| 3 性格 | 35 s | 「傲娇一点」→「你喜欢吃什么？」→「温柔一点」 | 同一个问题，前后语气明显不同 | 语气真的变了，不只是换词 | `azure_tts_first_audio … style=disgruntled`，然后是 `style=gentle` |
| 4 导航 + 打断 | 60 s | 「导航去励骏庞都」→「第一个」→「开始导航」；播报时说「好了停一下」 | 候选列表 → 路线 → 3D 导航，转向提示由晓伊播报；被打断时她马上停 | 地图内嵌；导航也是同一个声音；随时可打断 | `nav_route_candidates`、`nav_started`、`guidance_route to=assistant`、`playout_barge_in` |
| 5 收尾 | 20 s | 「放点梶浦由记的，空之境界里很燃的那首」 | 音乐 app 被打开去找；她只说确认过的事 | 说到就做到，做不到就直说 | `tool=play_music` |

**备选。**
- 时间不够时，删掉第 5 段，不要删第 2 段。
- 第 2 段是和别家拉开差距的地方。

**字幕里的延迟数字：**
- 只写本次日志量出的「说完 → 开口」时间，用 `check_demo_log.py` 报告里的值。
- 目标：聊天中位数 ≤ 2 秒，车控 ≤ 2.5 秒。
- 达不到就不写数字，不要估。

## 怎么录

1. **构建并装包。** 在 PC 上运行：
   ```powershell
   .\gradlew.bat test --rerun-tasks :app:assembleDebug
   .\scripts\emulator.ps1 -InstallApk
   ```
2. **设置，录之前做一次，不要入画。**
   - 开发者设置里填 Gemini key，勾同意。
   - 小诺的声音：填 Azure key 和 region，**勾「用 Azure 声音说话」**。
   - 打开「助手播报导航（实验）」。
   - 做完退出设置。之后不要再点「开发者设置」。
3. **准备用户语音。**
   - 用 `make_clips.py` 生成本次口令的音频，和上次一样用云希声音。
   - 片段名建议用 `s1_help`、`s2_mosquito`、`s2_out`、`s2_seat`、`s2_lower`、`s2_temp`、`s2_lower2`、`s3_tsundere`、`s3_food`、`s3_gentle`、`s4_nav`、`s4_first`、`s4_start`、`s4_stop`、`s5_music`。
4. **每段单独录。**
   - 用 `demo_rec.py … --record`。
   - 同时抓日志：`adb logcat -v threadtime -s NovaVoice > takes\<段名>.log`。
   - 第 4 段开始导航后，另开终端运行：
     ```
     adb shell am broadcast -a com.novadrive.app.DEBUG_TOOL --es tool nav_speed --es arg 60
     ```
     这样会有转向播报。
5. **每段先查日志再用。**
   - 对照上表最后一列，并运行：
     ```
     python tools\demo\check_demo_log.py --run B takes\<段名>.log
     ```
   - 报告里出现「本段该有」的 FAIL，就整段重录。
   - 场景没录到会显示 NOT_SEEN，这是正常的。
6. **合成。**
   - 在 `compose.py` 的 `SCENES` 里填入采用的 take，并裁掉开头的空等。
   - 右侧字幕用上表的「要点」。
   - 输出 `startup_demo.mp4`（1920×1080）。

**诚实规则（和上次一样）：**
- 失败的口令不能剪成看起来成功。
- 一段里有两个声音，或者她念出了「no speech」「pause」之类的字，整段丢掉。

## 失败时怎么收回

| 现象 | 处理 |
| --- | --- |
| 问完很久没声音（超过 5 秒） | 整段重录。并把日志留下，这是 P45 要的证据 |
| 听到两个声音，或者是 Gemini 自己的声音 | 检查「用 Azure 声音说话」是否勾上，并已保存；重开会话 |
| 「再低一点」第一次就去问「座椅还是温度」 | 顺序错了：「座位有点高」必须在它前面，且不要隔太久 |
| 导航没候选 | 再说一次「导航去励骏庞都」。不要换长路线 |
| 风格听不出区别 | 换「嗲一点」或「元气一点」，录完再挑最明显的两段 |
| 设置或密钥入画 | 丢掉该段 |
